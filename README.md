# meetup-event-vienna

The AWS User Group Vienna meetups for the meetup evening, one folder per
event. To add a meetup, paste its link:

## Part of the meetup tools

One of the repositories behind the AWS User Groups Austria meetup evenings, in
[aws-user-groups-austria](https://github.com/aws-user-groups-austria). Start with
[`meetup-workspace`](https://github.com/aws-user-groups-austria/meetup-workspace): it clones all of them (`make
clone`), installs them and runs the whole evening (`make start`); the contract
between them is its `SPEC.md`.

| Repository | What |
|---|---|
| [`meetup-workspace`](https://github.com/aws-user-groups-austria/meetup-workspace) | The Makefile, the spec and the guide |
| [`meetup-sync`](https://github.com/aws-user-groups-austria/meetup-sync) | A Meetup page to `event.json` |
| **[`meetup-event-vienna`](https://github.com/aws-user-groups-austria/meetup-event-vienna)** | One folder per meetup, shared photos and logos |
| [`meetup-stream-templates`](https://github.com/aws-user-groups-austria/meetup-stream-templates) | The room screen: Remotion scenes and the web player |
| [`meetup-deck`](https://github.com/aws-user-groups-austria/meetup-deck) | The slide deck, filled in |
| [`aws-community-austria-website`](https://github.com/aws-user-groups-austria/aws-community-austria-website) | awscommunity.at |


```sh
make new URL="https://www.meetup.com/amazon-web-services-aws-vienna/events/316893745/"
```

That fetches the page to work out the id (doors-open date plus a slug of
the title), creates `events/<id>/source.json` with the link and a short `README.md`, and runs
`make sync` for it, which writes `events/<id>/event.json`. Quote the link: zsh
treats `?` in an unquoted link as a pattern. Query strings such as
`?eventOrigin=...` are dropped.

This needs network access: it makes one request to the Meetup page. Without
network, save the page in a browser and pass it as `FROM=` (see below). If a
folder for that link already exists, it stops before fetching and names the
folder.

Needs `../meetup-sync` next to this folder; its dependencies are installed on
first use.

## Layout

```text
events/
  2026-10-20-aws-meetup-vienna-53/
    README.md       what the folder is (written by make new)
    source.json     the Meetup link and optional overrides (edit this)
    event.json      generated by meetup-sync (do not edit by hand)
    assets/         speaker photos, sponsor logo (optional)
    page.html       a saved Meetup page for sync-offline (optional, never committed)
    deck/           make deck output: header.jpeg and <id>.pptx (never committed)
    canva/          Canva exports for the deck: header.png, talk-1.png, ... (never committed)
deck/
  README.md
  aws-ug-vienna-austria.pptx   the group's deck, the template (never committed)
```

Saved pages are not committed: `.gitignore` ignores `events/*/page.html` and
every other `.html` file here, because a page saved from a logged-in browser
carries account data and session tokens.

`source.json`:

```json
{
  "meetupUrl": "https://www.meetup.com/amazon-web-services-aws-vienna/events/316893745/",
  "sessionize": "3epsgjj2",
  "overrides": {}
}
```

`sessionize` is the Sessionize API endpoint id (optional): it adds speaker
photos and fills other gaps, see `../meetup-sync/README.md`. `make sync`
fetches it; `make sync-offline` uses `events/<id>/sessionize.html` when you
saved one there (the endpoint's `?under=True` page), else skips it.

`overrides` is deep-merged into the generated file last: speaker photos,
sponsor logo, a feedback form, the venue name, a next-events link (the
20 October event sets `links.nextEvents` to `https://awscommunity.at/`). The merge
rules and an example are in `../meetup-sync/README.md`. Anything not on the
Meetup page and not in overrides stays absent.

## Speaker photos and sponsor logos

Put the files in `events/<id>/assets/` and point to them in `source.json`
with the path the web player sees, `events/<id>/assets/<file>`:

```json
{
  "meetupUrl": "https://www.meetup.com/amazon-web-services-aws-vienna/events/316893745/",
  "overrides": {
    "sponsors": [{ "name": "Raiffeisen Bank International AG", "logo": "events/2026-10-20-aws-meetup-vienna-53/assets/rbi.svg" }]
  }
}
```

`make player-event` in `../meetup-stream-templates` and `npm run present:sync`
in the website copy `events/<id>/assets/` next to the player as
`events/<id>/assets/`, so the same path works in the dev player, in the
stills (`make stills` there) and on `/present/`. A full `https://` URL works as
well and needs no copy. Only add a photo or logo once its owner has agreed.

## The slide deck

The deck the organizers present from, filled in for this meetup: the
meetup number, the Meetup header image, the sponsor, the agenda, one slide
per talk and break, and the closing with the feedback QR code. First save
the deck from Google Slides (File, Download, Microsoft PowerPoint) as
`deck/aws-ug-vienna-austria.pptx`, then:

```sh
make deck EVENT=2026-10-20-aws-meetup-vienna-53
```

It renders the stills in `../meetup-stream-templates`, downloads the header
image from Meetup once (the `image` in `event.json`) and writes
`events/<id>/deck/<id>.pptx`. It prints the visible slides in running order
and what is still to do (for now, the RBI logo). To present it from Google
Slides, upload the file to Drive and open it with Google Slides. What it
changes and how it finds the slides: `../meetup-deck/README.md`. Needs `uv`.

The talk slides and the header slide use the team's Canva designs when
they are in `events/<id>/canva/` as PNG (1920 x 1080): `header.png`, and
one per talk named after its segment id (`talk-1.png`, `talk-2.png`).
Without them the deck uses the stream's stills and the Meetup header image.

A sponsor logo for the deck must be a PNG or JPEG; for an SVG logo, put a
PNG of the same name next to it.

## Past meetups

Every past meetup on the group's Meetup page gets a folder too, for the
website's page per meetup and, where its agenda parses, present mode:

```sh
make archive
```

It reads the past-events page (the 10 most recent; Meetup shows no more on
that page), saves each event page once as `events/<id>/page.html`
(gitignored; `make archive REFRESH=1` fetches them again), creates
`source.json` when missing, and writes `meetup.json` (the website record,
`SPEC.md`) and `event.json` when the agenda validates. `make sync` writes
`meetup.json` as well. Photos, slides and recordings for a meetup's page go
into `source.json` under `media` (see `SPEC.md`, "meetup.json").

## The next AWS Community Days

`upcoming.json` lists the coming AWS Community Days with the community's
speakers. Every `make sync` puts the ones after that meetup's date (at most
three) into its `event.json` as `upcoming`: the stream announces the next one,
the deck gets a slide for it. Speaker photos shared by every meetup live in
`people/` and are referred to as `people/<file>`.

## Update an event

After the Meetup page changes, sync it again from the live page:

```sh
make sync EVENT=2026-10-20-aws-meetup-vienna-53
```

Or from a saved page, without the network. It uses `events/<id>/page.html`
when you saved one there, otherwise the matching page in
`../meetup-sync/tests/fixtures/`, or the file you pass as `HTML=`:

```sh
make sync-offline EVENT=2026-10-20-aws-meetup-vienna-53
```

```sh
make sync-offline EVENT=2026-10-20-aws-meetup-vienna-53 HTML=page.html
```

Every event with a saved page:

```sh
make sync-all-offline
```

`make new` also takes a saved page, so a new folder can be created without
fetching:

```sh
make new URL="https://www.meetup.com/amazon-web-services-aws-vienna/events/316893745/" FROM=page.html
```

All targets:

```sh
make help
```

If the generated file does not match the schema (for example a typo in an
override), meetup-sync prints the issues, exits non-zero, and leaves the old
`event.json` in place.
